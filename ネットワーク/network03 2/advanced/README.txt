第3回 発展版（必須ではありません）

基本版では「1回のrecvで全文がそろわない」ことを観察します。
この版では、繰り返して集める処理と、その終わりを決める方法を示します。

advancedフォルダへ移動してコンパイルします。
  g++ -std=c++17 server.cpp -o server
  g++ -std=c++17 client.cpp -o client
端末A：./server、端末B：./client
基本版のサーバは終了させておきます（同じTCP 8080番を使います）。

client.cppとserver.cppはnet_common.hppが必要です。
まずmainの流れを確認し、補助処理は必要に応じて読みます。
・sendAll：送信できた長さだけ位置を進め、残りを送る。
・receiveUntilEof：recvで受け取った長さ分を追加し、0まで繰り返す。
・クライアントは送信後shutdown(SHUT_WR)で送信側だけ終了。
・サーバは要求の終わりを確認して応答し、closeする。
・クライアントも応答を終わりまで受け取る。
空入力でも終了し、最大64 KiB。入力は1件のみです。

観察：client.cppのBUFFER_SIZEを4へ変えて再コンパイルし、helloを送信。
recvログは複数回になりますが、最後に全文helloを組み立てます。
基本版の「1回だけで終了する」結果と比較できます。
この版の送信終了方式は、同じ接続で複数発言するチャットにはそのまま使えません。
継続通信では改行や長さなどのメッセージ境界を別途設計します。

基本版と発展版のサーバ・クライアントを混ぜないでください。
タイムアウト、複数人、暗号化などはこの版にもありません。
