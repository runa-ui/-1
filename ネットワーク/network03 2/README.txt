ネットワークシステム 第3回 配布サンプル

【最初に使うファイル】
simple-server.cpp：サーバ。接続を受け付け、1回受信し、その分だけ返す。
simple-client.cpp：クライアント。入力を送り、1回受信して表示する。
threads.cpp：授業後半のスレッド比較デモ。
advanced/：任意の発展版。基本版の演習終了後に使う。
基本版に共通ヘッダは不要。mainから各関数へ読み進める。

【環境とコンパイル】
macOS / Linux / 用意済みのWSL、C++17対応のg++またはclang++。
同じOS環境の2つの端末で、このnetwork03フォルダへ移動する。
WindowsネイティブのWinsock用ではない。
  g++ -std=c++17 simple-server.cpp -o server
  g++ -std=c++17 simple-client.cpp -o client
  g++ -std=c++17 -pthread threads.cpp -o threads

【起動】
  端末A：./server
  Waiting on 127.0.0.1:8080 が出たら、端末Bで ./client
  Enter message: に hello と入力してEnter。
通常は両端末に Received 5 bytes: hello と表示され、両方終了する。
毎回サーバを起動し直す。別PCには接続しない。
終了できない場合は、そのプログラムの端末でCtrl+C。

【演習1：1往復を確認】
1. helloを送って、両方の端末の表示を記録。
2. サーバを起動し直し、日本語でも試す。
   バイト数と文字数は異なる。まずは短い入力を使う。
3. サーバを起動し直し、空のままEnter。
   再入力の案内が出ることを確認し、helloを入力して終了する。
   空入力は送らないため、その間サーバはrecvで待つ。

【観察：1回の受信で全文を読めるか】
1. simple-client.cppのBUFFER_SIZEだけを4へ変更して再コンパイル。
   サーバ側のBUFFER_SIZEやMAX_INPUT_BYTESは変更しない。
2. サーバを起動し直し、クライアントからhello（5バイト）を送る。
3. サーバとクライアントの受信長と表示を比べる。
   クライアントの1回のrecvは最大4バイト。全文にはならない。
   よくある結果は4バイトのhellだが、必ず4とは限らない。
   基本版は続きの受信を行わず終了する。
   TCPが残りを失った証拠ではなく、アプリの読取りが1回で終わるため。
4. BUFFER_SIZEを1024へ戻して再コンパイル。
※この変更はネットワーク上のパケット分割を指定するものではない。
※日本語の途中で区切ると文字が崩れるため、この観察はhelloを使う。

【演習2：ポートの不一致】
1. simple-client.cppのPORTだけを8081へ変更して再コンパイル。
2. 8080番のサーバを起動し、クライアントを実行。
   通常はconnect: Connection refused等。OSにより表記は異なる。
   8081番に別サービスがない環境を前提とする。
3. サーバは接続待ちのままか確認。
4. PORTを8080に戻して再コンパイルし、同じサーバへ接続。

【入力待ちの観察】
クライアントの入力欄で、数秒Enterを押さずに待つ。
クライアントはgetline、接続済みのサーバはrecvで待つ。
空でない文字列を確定すると通信が進む。

【基本版で意図的に省いていること】
・送受信は各1回。短い文字列でも全文を一度で受信できる保証はない。
・sendの戻り値は確認する。全量を渡せなければ表示して終了し、再送しない。
・入力上限1024バイトは入力制限であり、一度の受信でそろう保証ではない。
・受信した長さだけ表示・返信する。strlen(buffer)には依存しない。
・アプリのメッセージ境界をまだ実装していない。
・タイムアウト、EINTRの再試行、複数人、継続チャット、暗号化は扱わない。
・空入力は再入力。標準入力が閉じた場合は接続を閉じて終了。

【スレッドの比較】
  ./threads serial  # Aの後にB。約6秒。
  ./threads         # AとBを並行に。約3秒。
1秒の待機を3回ずつ行う。計算速度が常に2倍になる意味ではない。

【発展版】
advanced/README.txtを参照。送信の残り、受信の繰り返し、終了条件を扱う。
基本版と発展版は、それぞれ同じ版のサーバ・クライアントを組にする。
特に基本版クライアントと発展版サーバを混ぜると終了合図がなく待ち続ける。
